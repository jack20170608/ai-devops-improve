提示词工程基础

前置知识： 了解 AI 基本概念，熟悉 LLM 的基本原理

提示词工程（Prompt Engineering）是与大型语言模型（LLM）高效交互的核心技能。它涉及设计、优化输入提示词，以获得更准确、更有价值的输出。掌握提示词工程，能够让你充分发挥 AI 的能力，大幅提升工作效率。

1. 为什么提示词工程重要？

LLM 的输出质量高度依赖于输入提示词的质量。同一个模型，不同的提示词可能产生截然不同的结果。好的提示词能够：

  • 提高准确性：获得更精确、更相关的回答
  • 减少迭代：减少来回修正的次数
  • 扩展能力：解锁模型的高级功能
  • 控制输出：获得符合特定格式或风格的结果
关键洞察： 提示词工程不是「欺骗」AI，而是学会如何清晰地表达你的需求。正如好的问题需要精心设计，与 AI 的沟通也需要技巧。

2. 提示词核心原则

2.1 清晰明确（Clear）

你的指令越清晰，模型越能理解你的意图。避免模糊或多义的表达。

# ❌ 模糊的提示词
"写一些关于Python的东西"

# ✅ 清晰的提示词
"写一个Python函数，计算列表中所有偶数的和，并包含类型注解和单元测试"

2.2 具体详细（Specific）

提供足够的上下文和具体要求，让模型知道确切需要做什么。

# ❌ 过于笼统
"帮我写一封邮件"

# ✅ 具体详细
"写一封邮件给客户，内容是：
- 主题：项目进度更新
- 开头礼貌问候
- 说明本周完成的3个功能
- 提及下周的里程碑
- 结尾期待合作
- 语气专业但亲切"

2.3 结构化（Structured）

使用清晰的结构组织提示词，模型能更好地理解和执行。

# 结构化提示词示例
"""
任务：审查以下Python代码

代码：
```python
def process_data(data):
    results = []
    for item in data:
        if item['active']:
            results.append(item['value'] * 2)
    return results
```

要求：
1. 指出代码中的问题
2. 提出改进建议
3. 提供优化后的代码

输出格式：
- 问题列表（编号）
- 建议列表（编号）
- 优化代码（代码块）
"""

2.4 提供上下文（Context）

给模型足够的背景信息，帮助它理解你的需求场景。

# ❌ 缺乏上下文
"如何实现认证？"

# ✅ 有上下文
"我正在开发一个Node.js的REST API后端服务，使用Express框架。
需要实现用户认证功能：
- 使用JWT令牌
- 支持刷新令牌
- 密码需要加密存储
- 预计日活用户10万

请提供实现方案和关键代码"

3. 提示词模式与技巧

3.1 角色扮演（Role Playing）

让模型扮演特定角色，可以获得更专业的输出。

# 角色扮演示例
"你是一位拥有10年经验的高级Python工程师，擅长编写高性能、易维护的代码。
请审查以下代码，指出可以优化的地方：

```python
def find_duplicates(lst):
    seen = set()
    duplicates = []
    for item in lst:
        if item in seen:
            duplicates.append(item)
        seen.add(item)
    return duplicates
```

请从以下角度审查：
1. 性能
2. 代码风格
3. 错误处理
4. 可读性"

3.2 few-shot 学习（示例引导）

提供输入输出示例，帮助模型理解你的期望格式。

# Few-shot 示例
"""将以下命令转换为自然语言描述：

示例：
git push -u origin main -> "将本地main分支推送到远程origin仓库，并设置为上游分支"
git merge feature/login -> "将feature/login分支合并到当前分支"
git reset --hard HEAD~3 -> "将代码库回退到3个提交之前"

请转换：
git rebase -i HEAD~5
"""

3.3 思维链（Chain of Thought）

引导模型展示推理过程，可以提高复杂任务的准确性。

# 思维链提示
"""请逐步推理以下问题：

问题：如果一个球队赢了60%的比赛，当他们先得分时，胜率提高到70%。先得分的比赛占40%。请问先得分对获胜的提升是多少？

请按以下步骤推理：
1. 定义变量
2. 计算相关概率
3. 列出公式
4. 计算结果
5. 给出答案
"""

3.4 分步指令（Step-by-Step）

将复杂任务拆分成多个步骤，逐一完成。

# 分步指令示例
"""帮我创建一个REST API用户接口，请按以下步骤进行：

步骤1：定义数据模型
- 用户包含：id, username, email, password_hash, created_at, updated_at
- 使用SQLAlchemy

步骤2：创建API端点
- POST /users - 创建用户
- GET /users/{id} - 获取用户
- PUT /users/{id} - 更新用户
- DELETE /users/{id} - 删除用户

步骤3：添加认证
- 使用JWT
- 实现登录接口

请依次提供每个步骤的代码"

3.5 格式化输出（Output Formatting）

明确指定输出格式，方便后续处理。

# 格式化输出示例
"""分析以下Python代码的性能问题，提供JSON格式的输出：

代码：
```python
def slow_function(items):
    result = []
    for i in range(len(items)):
        for j in range(len(items)):
            if items[i] == items[j]:
                result.append(items[i])
    return list(set(result))
```

输出格式：
{
  "issues": [
    {"severity": "high/medium/low", "description": "...", "line": "..."}
  ],
  "suggestions": [
    {"description": "...", "code": "..."}
  ],
  "optimized_code": "..."
}"""

3.6 约束限制（Constraints）

明确告诉模型什么是不要的，避免不期望的输出。

# 约束限制示例
"""用Python实现一个排序算法，要求：
- 时间复杂度O(n log n)
- 不能使用任何内置排序函数（如sorted, list.sort）
- 代码需要包含类型注解
- 需要有docstring文档
- 不要使用任何第三方库

请提供完整代码"""

4. 高级技巧

4.1 迭代优化

提示词往往需要多次迭代才能达到理想效果。

迭代轮次 提示词 改进点
第1轮 写一个排序函数 基础要求
第2轮 写一个快速排序函数，包含单元测试 明确算法和测试要求
第3轮 用Python实现快速排序，包含类型注解、docstring、完整的单元测试，覆盖边界情况 完整的技术要求

4.2 系统提示词（System Prompt）

系统提示词设置 AI 的行为模式和整体约束。

# 系统提示词示例
系统提示词：
"你是一位专业的技术文档工程师，擅长用清晰、简洁的语言解释复杂的技术概念。
你的写作风格：
- 使用简洁的句子
- 多用例子说明
- 适当使用代码示例
- 避免过度技术化的术语，必要时解释"

用户提示词：
"解释什么是异步编程"

4.3 温度参数（Temperature）

控制输出的随机性，不同任务需要不同的设置。

Temperature 值 特点 适用场景
0.0 - 0.2 确定性高，创意少 代码生成、翻译、事实性问题
0.5 - 0.7 平衡 日常对话、内容创作
0.8 - 1.0 创意性强，变化多 头脑风暴、创意写作

4.4 提示词模板

# 常用提示词模板

# 模板1：代码审查
"""作为[语言]专家，审查以下代码：
[代码]

请从以下角度分析：
1. [角度1]
2. [角度2]
3. [角度3]

输出格式：[格式要求]"""

# 模板2：代码生成
"""用[语言]实现[功能]，要求：
1. [要求1]
2. [要求2]
3. [要求3]

约束条件：
- [约束1]
- [约束2]

请提供完整代码"""

# 模板3：问题解答
"""作为[领域]专家，回答以下问题：
[问题]

要求：
- 提供详细解释
- 包含代码示例（如果适用）
- 指出常见的误区
- 推荐进一步学习的资源"""

5. 常见问题与解决方案

5.1 输出太简短

# 问题：模型回答过于简洁
# 解决：明确要求详细程度

"详细解释Python装饰器的工作原理，至少包含：
- 概念介绍
- 语法说明
- 3个实际使用例子
- 注意事项
- 每个部分不少于100字"

5.2 输出格式混乱

# 问题：输出格式不统一
# 解决：提供清晰的格式规范

"""请以以下JSON格式输出分析结果：
{
  "summary": "一句话总结",
  "pros": ["优点1", "优点2"],
  "cons": ["缺点1", "缺点2"],
  "recommendation": "最终建议"
}

分析对象：[分析内容]"""

5.3 理解有偏差

# 问题：模型理解与预期不符
    # 解决：提供更多背景和示例

    """关于[主题]，请注意：
- [背景1]
- [背景2]

示例参考：
输入: [示例1]
期望输出: [期望1]

输入: [示例2]
期望输出: [期望2]

现在请处理：
[实际输入]"""

5.4 知识过时

# 问题：模型知识截止日期导致信息过时
# 解决：明确说明需要最新信息

"""请查找[主题]的最新信息（2024年及以后）。
如果以下信息已过时，请指出并提供最新版本：
[已知信息]

请说明信息来源和日期"""

6. 实践练习

练习1：优化提示词

将以下提示词优化为更有效的版本：

# 原始提示词
"写一个Python程序"

# 优化方向
- 明确程序功能
- 指定输入输出
- 添加约束条件
- 指定代码风格

练习2：编写提示词

为以下场景编写提示词：

  1. 让 AI 扮演资深架构师，审查微服务设计方案
  2. 生成符合公司规范的 API 文档
  3. 创建技术博客文章的大纲
  4. 调试一段有问题的 SQL 查询

7. 总结

提示词工程是一项需要不断实践的技能。掌握以下核心要点：

  • 清晰明确：让你的需求准确传达
  • 提供上下文：给模型足够的信息
  • 结构化：组织好提示词结构
  • 使用示例：Few-shot 往往很有效
  • 迭代优化：不要期望一次就完美
技巧 适用场景
角色扮演 需要专业知识的任务
Few-shot 需要特定格式输出
思维链 复杂推理问题
分步指令 多步骤复杂任务
格式化输出 需要程序化处理的结果
约束限制 需要特定风格或限制
